# R-15 / S025 — запуск без обязательного ожидания

Исправлен локальный код, выполнена браузерная приёмка. **Проверка cold/warm/offline на прежнем физическом Android остаётся открытой.** ADB не видит устройство; владелец прямо поручил продолжить без телефона. Версия Play не менялась.

Заставка снимается после настройки обработчиков UI и завершения account bootstrap. Она не ждёт необязательные картинки, шрифты и window.load; minimum5,5с и преждевременный session-skip убраны. Снятие — на ближайшем кадре. Warm reload тоже ждёт реальную готовность, а не скрывает ещё неработающий интерфейс.

Запрос сессии ограничен6с через AbortController, включая чтение ответа; cached-account поведение сохранено. Ошибка сети оставляет понятное уведомление с кнопкой повторной попытки, не выдаёт новые денежные права. Если критический JS завис при загрузке или модуль не загрузился, максимум через8с таймера JS показывается экран ошибки с retry. При успешной поздней загрузке он снимается штатно. Заблокированный JS event loop сам по себе этим таймером не лечится.

Уведомления AZ/RU/EN используют сохранённый `domino-lang`. Сообщение о сети встроено в поток страницы: на320px не закрывает вход/правила. Снимки [offline](offline-320.png) и [ошибка модуля](module-error-320.png) просмотрены. На маленьком экране длинная карточка прокручивается. Кнопка retry проверена с реальным reload и последующим открытием меню; возникновение online-события само по себе не объявляет сервер доступным.

## Проверки и измерения

Новые10тестов на web/www: холодный/повторный запуск, задержанный account на warm reload, зависшая необязательная картинка/window.load, offline/retry, зависший account request, отказ/возврат модуля, deadline при зависшей загрузке,320px. Node22:10/10; Node25:все10прошли в полном E2E. Старый код воспроизводит ошибки в новых сценариях. Финальный cold-only red run использует неизменённые исходники `eb8b21e` в отдельной копии.

Полные проверки: server390/397 и E2E53/62, ровно те же7/9старых падений; [сравнение имён](failure-delta.json). Нет новой ошибки, но общий набор не зелёный. API148/148на Node22/25 относится к соседнему S024.

[Метрика](timing-summary.json): headless Chromium390×844, синтетический моментальный API,3пары cold/warm. Cold здесь — новый browser context, а не очистка OS/disk cache. Контрольное открытие меню после удаления DOM заставки: медиана cold примерно6,35с→0,15с; warm примерно0,117с→0,113с. Probe сначала ждёт удаления DOM: старый CSS отключает pointer-events до700мс fallback-удаления, поэтому это **верхняя оценка проверенного открытия**, не измерение самого раннего возможного касания. Эти числа не являются результатом Android, production-сети или гарантией скорости на любом компьютере. Заявляемое исправление — удаление обязательной паузы и ограничение неопределённого ожидания.

Временные ошибки стенда/исправления UI перечислены в summary.json. Assertions не ослаблены. Телефонные cold/warm/offline interactive метрики нужно снять при следующем доступе к устройству; до этого R-15 сохраняет незавершённую приёмку.
