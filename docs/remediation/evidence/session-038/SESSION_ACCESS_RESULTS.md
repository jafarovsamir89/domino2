# S038 — R-10: отзыв уже открытого соединения

Решение владельца21октября: отключать соединение не позднее60секунд после logout/блокировки/удаления, затем использовать обычные disconnect/grace/forfeit правила. Локальная реализация принята по этому решению; production не менялся.

`server/roomSessionAccess.js` выделяет HTTP-валидацию из DominoRoom и проверяет активные места каждые20секунд. Каждый HTTP-запрос ограничен3секундами; штатный верхний интервал обнаружения23секунды. При отказе/недоступности API новые сообщения места блокируются, соединение закрывается4003. Существующий onLeave управляет grace/итогом/кошельком. Монитор сам монеты не трогает. API не вызывается на каждый ход.

Пятиминутный admission token не должен выкидывать игрока из долгой партии. Новый серверный POST `/api/platform/game-session/validate` принимает исходный подписанный token с проверкой текущей DB-сессии, владельца player и активного бана. Истёкший token допустим только здесь при свежей серверной подписи scope `game.session.validate` и timestamp±10секунд. Обычные join/reconnect по-прежнему требуют неистёкшего допуска. Истёкшая/удалённая DB-сессия, удалённый player, ban или несовпадение владельца отклоняются.

Защита учитывает замену identity/client, повторный опрос, синхронный отказ validator, shutdown и поздние ответы. Клиент прекращает повтор старого reconnect token и сохраняет multiplayer mode, чтобы отключённая партия не стала локальной. Снимок собственного места остаётся для последующего входа с новым разрешённым аккаунтным допуском.

Проверки: новый module contract отсутствовал до реализации; API regression падал на отсутствующем методе. После реализации targeted server/auth/network33/33; API auth7/7. Общая матрица S038 и итоговые числа в `TEN_CARD_RESULTS.md`. Все identities/HTTP/DB substitutes синтетические и локальные. JSON room/snapshot contracts не менялись.

Будущий выпуск: **сначала API с новым endpoint, потом игровой сервер**, с одинаковым server proof secret и синхронными часами. Старый API вернёт404 и новый guard закроет активные соединения;5xx/429/network тоже fail closed. До локальной приёмки релиза проверить эту последовательность. Под нагрузкой задержка event loop может увеличить wall-clock;23секунды — таймер+HTTP deadline в нормально работающем процессе, а не гарантия во время зависания ОС. Никакого deploy этой сессией не выполнялось.
