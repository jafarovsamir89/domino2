## Что удалось завершить

Владелец передал ответ Unity: поддержка изменила настройку у себя и попросила повторить Test callback, а при сохранении ошибки — запись Network и очищенный HAR. Это стало новым основанием для повтора ранее неуспешной проверки. Использован уже разрешённый отдельный signature-only приёмник: без Prisma/API игры/пользователей/кошельков, новый временный HTTPS через Cloudflare, новая отдельная тестовая пара key/nonce.

Первый повтор с прежним генератором снова показал ошибку. Настоящий callback прошёл проверку подписи и получил originHTTP200, но браузерный запрос кабинета к `/api/rest/v1/monetize?appKey=28e969915` завершился HTTP400. В открытом DevTools → Network → Response обнаружено точное объяснение: **`Invalid callback.privateKey (too long)`**, field`callback.privateKey`, internalCode381. В генераторе использовались32случайных байта, которые после hex-кодирования давали64символа. Это была ошибка подготовки нашего теста.

Выполнена ещё одна проверка с новым случайным ключом16байт/32hex-символа и новым256-bit nonce. Приёмник перезапущен с новой конфигурацией, тот же временный HTTPS сохранён. **Кабинет показал `Your callback settings are valid`, запрос кабинета HTTP200.** XML ACK `<status>EVENT_ID:OK</status>`, byte Content-Length и no-transform оставлены без изменения. Общий опубликованный предел длины ключа этой проверкой не установлен: доказано только, что64были отвергнуты,32приняты.

Поэтому нельзя приписывать весь результат только изменению Unity или утверждать, что установлена причина всех исторических отказов S042/S043. Факты: после сообщённого изменения Unity64-символьный ключ вернул381, затем32-символьный прошёл. Старые доказательства не переписаны.
