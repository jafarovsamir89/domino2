# S023 / R-14 — постоянные эффекты и проверка на Android

Внесены локальные изменения CSS и сняты два замера: диагностические вмешательства по отдельности и сравнение старого/нового оформления. Проверялся только `az.simplesoft.dominotelefon.audit`, с локальным синтетическим UI API. Рабочая версия из Play не менялась.

## Что изменено

- Убраны бесконечные `tileGlow`, `activeTurnPulse` и `arrowPulse`, перерисовывавшие большие тени. Допустимая костяшка и активная рука отмечаются статической золотой рамкой.
- Постоянные панели руки/счёта и DOM-стрелки больше не размывают фон.
- У маркера Konva убраны большие тени и фильтр; осталась короткая анимация прозрачности в два повтора. После неё маркер виден и принимает нажатия. При reduced-motion анимация выключена.
- Web и `www` синхронизированы. Рамки и анимации не изменяют правила хода и денежные расчёты.

## Стенд и границы вывода

Телефон2201117SG, Android13, установленная тестовая копия на Capacitor8.5.3; USB reverse к localhost4175. Одна и та же сцена из28костяшек, построенная легальным последовательным fixture. В руке дополнительно7синтетических костяшек: это нагрузка на renderer с видимыми подсказками, а не доказательство законной партии с35костяшками. Правила/таймеры остановлены. Canvas ratio1,25 одинаков во всех вариантах, чтобы не приписывать CSS эффект R-13.

`requestAnimationFrame` измеряет ритм JS-цикла. SurfaceFlinger `--latency` даёт интервалы фактических presentation; они включают намеренные паузы, когда в сцене ничего не меняется. Perfetto FrameTimeline отдельно измеряет длительность обработки/представления app frame, включая GPU. Эти три величины не взаимозаменяемы. Метод FrameTimeline описан в [документации Perfetto](https://perfetto.dev/docs/data-sources/frametimeline).

## Отдельные диагностические вмешательства

Три блока, порядок вариантов перемешан фиксированным seed, каждое окно8с, последний tile travel раз в650мс. Между окнами500мс. В первой серии температура батареи37,5–37,9°C; телефон на зарядке. Это не лабораторная стабилизация теплового режима.

Первичная серия: [effects-ab.json](effects-ab.json). В ней `shadow_only` фактически убирал **и box-shadow, и filter**, поэтому этот вариант нельзя считать чистой оценкой теней. Для устранения неоднозначности выполнена дополнительная серия [effects-paint.json](effects-paint.json): отдельные box-shadow-only и filter-only, тоже по три окна каждого варианта. Прямые сравнения делаются внутри своей серии.

Чистая серия дала медиану rAF/s около21исходно,54без box-shadow и20без filter. Таким образом, в этой сцене большой вклад подтверждён именно у теней; одного отключения filter недостаточно. Таблица медиан по каждому варианту находится в [isolated-summary.json](isolated-summary.json). Первая серия показывает существенный вклад постоянных анимаций и композиции; чистая дополнительная серия отделяет тени от фильтра. Отключение всех анимаций создаёт неподвижные интервалы, поэтому длинные native intervals у такого варианта не объявляются задержками кадра.

## Повторение

На чистом checkout установить зависимости из lockfiles в изолированную копию через `prepare-checkout.mjs`/`run-check.mjs`, затем запустить `playwright test e2e/renderer-quality.spec.mjs e2e/game-effects.spec.mjs`. Полные browser runners выполнять последовательно либо на разных портах. Нужен Chromium, соответствующий установленному Playwright.

Для телефона нужна отдельная `.audit` сборка с URL4175 и `renderer-preview.mjs`, привязанным только к localhost. `device-effects.mjs` выполняет исходную серию; аргумент `paint` — уточняющую. `device-effects-product.mjs` требует локальный [официальный Trace Processor](https://perfetto.dev/docs/quickstart/trace-analysis); в этом прогоне использован58.2, проверяемый launcher и версия записаны в provenance. Данные FrameTimeline доступны начиная с Android12. На Play-пакет скрипты не направлять. После работы убрать только созданные mappings/files и остановить свой стенд.
