# R09 — настройка кабинетов через Chrome, 2026-10-21

Владелец прямо поручил: «@Chrome Продолжай настройку LevelPlay». Chrome подключён через расширение. Работа выполнялась только через наблюдаемый интерфейс кабинетов. Это настройка провайдера, не обновление production/Play и не закрытие R09. Счёт27/42.

## Подтверждённые изменения

- В LevelPlay форма уже содержала импортированную опубликованную игру Domino Club Online, пакет `az.simplesoft.dominotelefon`. Выбраны `Puzzle: Board` и COPPA `Not directed` по ответу владельца: аудитория13–17+взрослые, без младше13. Restricted users не менялись. Сохранение подтверждено сообщением `Your app has been created` и переходом к Ad units.
- Создан единственный `Daily Bonus Rewarded`, формат `Rewarded`, new setup, reward item `Daily bonus boost`, amount1. Это одна возможность удвоения, не одна монета и не фиксированная сумма daily. Будущий сервер обязан сам проверить исходный daily, уникальность события и1грант/Baku-day. Provider capping/pacing оставлены по умолчанию выключенными; защита ещё не подключена к этому новому провайдеру.
- Список Ad units показал1из1. Автоматически созданная конфигурация содержит1network/1mediation group; это **не доказательство подключения Unity Ads**. Экран Networks→Unity→Setup требует API Key и Organization Core ID; поля оставлены пустыми, секреты не извлекались/не отправлялись.
- В Chrome Unity Dashboard уже был авторизован. Добавлены отдельный проект Domino Club Online и Android-приложение из Play URL. На вопрос о преимущественно детской аудитории выбран No, исходя из общей аудитории по ответу владельца. Существующие другие проекты не изменялись.
- Предложения расширенного Developer Data sharing не включались: приветственное предложение закрыто, в добавлении приложения использован `Continue`, а не `Enable and continue`. Юридические соглашения/подписи не принимались. Приложение видно в Apps,1приложение,0impressions.

## Выплаты и следующий шаг

В Unity Payments фактически указана страна Azerbaijan, однако payout profile **Not set**. Overview первоначально показал выплаты on hold, отсутствие налоговых форм и незавершённый расчёт payability. Это не подтверждение доступности выплат физлицу в Азербайджане. Billing information не заполнены, переводы дохода в рекламный бюджет не настроены и не менялись.

Открыт payout profile в iframe сервиса `ui2.tipalti.com`. Первый вход долго показывал spinner и не давал содержимого; после закрытия и повторного открытия через `Set up payout profile` iframe начал отображать интерфейс. **Текущий шаг — Set up 2-step verification: нужен номер телефона владельца и SMS-код.** Надпись сообщает, что только подтвердивший сможет менять способы выплат этого аккаунта. Номер/код и финансовые/налоговые данные не вводились, профиль не завершён агентом. Защитный шаг передан владельцу. В Chrome оставлены две вкладки: LevelPlay на неподключённой сети Unity Ads и Unity Dashboard с этой формой; обе отмечены handoff.

Следующая последовательность: владелец сам вводит телефон и подтверждает2FA, сообщает «номер подтверждён»; агент читает только следующий экран и помогает пройти необходимые личные/платёжные/налоговые шаги. Затем проверить результат payability и допуск. После этого связать Unity Ads с LevelPlay с отдельным согласованием передачи ключа/создания доступа, настроить тестовый режим, протокол S2S и SDK только в audit APK. Учитывать возрастные ограничения конкретных пользователей при инициализации SDK; `Not directed` не означает, что все игроки взрослые. Не включать client-only начисление или существующий AdMob ECDSA verifier для Unity/LevelPlay.

Скриншоты и идентификаторы кабинетов сохранены только локально в игнорируемой `.tmp/s040-levelplay/`; реальных ключей в Git нет. Журналы отражают действия, исходные аудит-доказательства сохранены. SDK/плагины агентом не устанавливались; production/Play/кошельки не менялись. Код не менялся, повтор тестовых наборов не требовался.
