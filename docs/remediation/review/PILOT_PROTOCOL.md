# R34–R38: кандидаты, пока выключены

S039. Это подготовка к решению, не результаты роста. Прототипы запускаются только в изолированной локальной сборке. Обычный сайт/Play остаются без них. Нельзя начинать реальные когорты до зависимостей и измеренной стабильности из REMEDIATION_PLAN.

## R34 — один вариант первого знакомства

`guided-solo-v1`: один экран объясняет бесплатную solo, отсутствие обязательного аккаунта/монет и ведёт к существующему выбору правил. Тексты AZ/RU/EN, TR не обещан. `reviewPilot.js` собирает только локальные события первого старта, старта и первого результата настоящей solo. Результат не удваивается при повторном render. Это не серверное подтверждение online победы. Экспорт из панели остаётся локальным, без сетевой аналитики.

Предлагаемый протокол для утверждения: контроль — текущий путь, вариант — один экран. Основная метрика — доля новых установок, завершивших первую полную партию за24часа (не отдельную раздачу). Дополнительные — время до старта, D1/D7, ошибки, отказы входа. Единица распределения — согласованная анонимная установка, стабильное50/50распределение; после согласования аналитики/согласий. До сравнения определить окно и размер выборки по baseline; при≈50пользователях причинный вывод может быть недоступен. Не объявлять победителя по десяти сессиям. Черновое правило остановки: любое расхождение ledger/правил — немедленно; ухудшение crash-free более0.5процентного пункта либо first-match более5пунктов против контроля в двух суточных окнах — выключить и разобрать. Эти пороги и метод статистики владелец ещё не утверждал.

## R35 — повтор и приглашение

Существующая кнопка после solo начинает следующую игру; для online существующая кнопка возвращает в лобби. Не обещать создание новой комнаты тем же составом автоматически. Локальный счётчик rematch измеряет нажатие, а не подтверждённую вторую партию.

Совместный прогон: клиентA/B входят синтетическими аккаунтами в локальный API/game; становятся друзьями; Aсоздаёт закрытую комнату и приглашает Bчерез свободное место; Bпринимает; оба завершают матч; возвращаются в лобби и создают ответный. Повторить при duplicate accept, просрочке, отмене, разрыве и повторном входе. Новый service-contract тест использует общий repository stub: это покрытие поведения APIметодов, не имитация доказательства двух браузеров/живого матча.

До реального измерения нужен согласованный серверный случайный invite-cohort token, связанный с итоговым durable match event и дедупликацией; не отправлять реальные player IDs, текст чата или private roomCode. Локальные invite_sent события сейчас считают успешные ответы транспорта, могут включать повторный ответ и не являются уникальной воронкой invite→completed match.

## R36 — добровольный rewarded

Серверный кандидат: сначала обычный daily, затем одно удвоение по проверенному SSV; одна награда/сутки Asia/Baku, максимум3попытки, согласие на запуск, отмена и10минут действия. Временные лимиты — конкретный черновик для обсуждения. Незавершённая/отменённая реклама не даёт монет; callbackamount не выбирает награду. Проверены подпись и атомарность в новой локальной PostgreSQL. APIroute/nativeSDK/productionDDL не подключены. Текущий dailyrewardedпо-прежнему403.

Реальная интеграция требует: выбор провайдера/блока, официальный тестовый SDK, фиксированный источник ключей Google с обновлением не реже24часов и bounded timeout, настройка callback в кабинете, проверка реального SSV, политика consent/Data Safety, отдельная миграция с backup/retention, проверка active ban/deletion на issue/consume, anti-abuse, rollback и согласованный бюджет R33. Не подключать этот кандидат к liveкошельку напрямую. Начальный rollout — только отдельно согласованная тестовая группа; kill switch запрещает новые attempts/grants. Уже подтверждённые начисления не удалять при rollback. Chargeback/compensation требует отдельной immutable ledger записи и согласованного правила, не delete старой записи.

Сравнивать фактически выплаченный net ad revenue после корректировок, добавленные монеты, D1/D7 и crash-free с контролем. Не обещать доход по числу локальных callback.
